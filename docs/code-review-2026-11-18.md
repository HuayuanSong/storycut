# StoryCut review, 18 November 2026

StoryCut generated a fresh storyboard and three playable videos on the public Space, including one with real LTX motion. The most consequential defect is in the editor. A job started on an earlier storyboard can replace subsequent edits or present an obsolete download as ready. Dark mode also makes essential text nearly invisible. Both warrant fixes before promoting the Space more widely.

I reviewed GitHub `7b14d31` and the running Hugging Face revision `28e91d6`. All 18 files selected by the deployment script matched byte for byte. The checks below used the public Space, its embedded browser interface, and an isolated checkout for failure tests and local model inference. [GitHub revision](https://github.com/HuayuanSong/storycut/tree/7b14d31e5938dc312adc69b23e16fb4efc4948dd) · [Space revision](https://huggingface.co/spaces/huathedev/storycut/tree/28e91d63e52cccb8b422a877efdc5ec3ed6d6421)

**Release follow-up.** The subsequent editor release addresses findings 1–4 and checks both JavaScript assets during deployment validation. The numbered findings and measurements below describe the reviewed revisions.

## Findings in priority order

1. **High · An older job can overwrite a newer edit or publish the wrong export.** On the live Space, I started a 30-second narration check and switched the editor to 45 seconds. The result restored the 30-second timing beside the selected 45-second target. In a local browser using the real renderer, I submitted “Walk A” at 30 seconds, then changed the title to “Walk B” and the target to 45. StoryCut switched to Watch & download and marked the old video ready. Its ZIP still contained “Walk A” and a 30-second target. I also started a real local Qwen draft, loaded the example, and edited its title while Qwen was working. Its late response replaced my edit. Give each session a project/edit revision and check it **when applying** a result, including automatic tab changes. A stale completion should leave the current work in place. The existing check when accepting a suggested script revision provides a precedent. [Draft and timing handlers](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L241) · [Render and edit handlers](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L267) · [Revision acceptance](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L123)

2. **High · Dark mode makes the editor difficult to read.** In the public Hugging Face embed with a dark system preference, the title text had a contrast ratio of **1.08:1** against its background. The same title measured **15.02:1** in light mode. Editor status text had the same problem, and the introductory paragraph measured about **1.00:1** in dark mode. Gradio switches its text colors while StoryCut supplies fixed light surfaces. Define foreground and background colors together for both modes. Add a browser check for actual computed contrast on the title, editor status and navigation. WCAG AA calls for 4.5:1 on normal-sized text. [App colors](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/assets/style.css#L1) · [Workspace styling](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/assets/style.css#L16) · [WCAG contrast criterion](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

3. **High · A new storyboard inherits the previous project’s images and AI-motion choice.** In the live editor I attached four identifiable review illustrations, enabled AI animation, then returned to Start and loaded the example. Its title and scenes replaced the previous story, but all four files remained selected and AI motion stayed on. The renderer consumes the uploaded files in scene order. Matching scene counts can produce a film with the wrong pictures and use the visitor’s GPU allowance. A different count stops export. Clear project-specific media and motion consent whenever a replacement storyboard is applied. Preserve them when revising the same storyboard. [New storyboard callbacks](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L243) · [Upload validation and selection](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/render.py#L110)

4. **Medium · A script expansion can meet its duration entirely through repetition.** I took the live Qwen sundial draft, measured it with Kokoro, and used the same pinned Qwen model locally to expand it from 30 to 45 seconds. The suggestion grew from **85 to 144 words**. All **59 added words** came from six sentences already present in their respective scenes. Kokoro measured 44.4 seconds, so the interface correctly reported that it fit. The repetition became visible when reading the two scripts side by side. Filter newly proposed sentences against the original narration and one another before counting progress. If no useful additions survive, keep the original and explain that the suggestion did not add material. This example establishes the failure mode. Its frequency would require a larger sample. [Expansion prompt](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/models.py#L87) · [Sentence selection](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/models.py#L109)

5. **Medium · A revision can attach narration to the wrong visual.** In a separate controlled test, a valid two-scene model response returned an orchard and a train in reverse order. Both revision modes accepted it. The train then received narration about apples, and the orchard received narration about wheels. The merge checks scene count and assigns narration by position. Give scenes stable IDs for revision, validate that every original ID occurs exactly once, and assemble the result in original order. The author’s headings and image choices can then be preserved even when the model changes its output order. [Revision merge](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/models.py#L109)

6. **Medium · Two dependency failures send users down the wrong recovery path.** In an isolated render, a simulated Wikimedia Commons HTTP 503 with animation enabled produced a message about GPU availability and quota. The motion model had received **zero calls**. Identify the failed stage so image-search errors can offer retry or image upload. Separately, an injected Qwen tokenizer load failure on the hosted startup path stopped the app before the editor opened. Preserve ZeroGPU’s model preload requirement, catch a failed preload, and make the example, editing, CPU narration and photo export accessible while the writer is unavailable. The optional motion model already has a degraded-startup path. [Image lookup](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/media.py#L67) · [Render error handling](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L143) · [Writer startup](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/models.py#L41) · [Motion startup](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/storycut/motion.py#L51)

7. **Medium · The mobile form shifts substantially during startup.** In three cold Chromium runs on the direct app at 390 × 844, with 4× CPU throttling, 1.6 Mbit/s download and 150 ms simulated latency, largest contentful paint was **4.64–4.79 seconds** and cumulative layout shift was **0.35**. The example button became available in 3.87–4.37 seconds. A separate layout trace showed the top of the workspace moving from **146 to 515 pixels** as the content above it appeared. Reserve the introductory section’s space during initialization and remeasure the same profile. These are controlled lab measurements. The existing wheel-scrolling fix worked in the actual embed. [Intro and workspace](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L162) · [Layout shift measurement](https://web.dev/articles/cls) · [Largest contentful paint](https://web.dev/articles/lcp)

8. **Medium · Deployment validation can pass a release that cannot start.** In a clean copy I removed only `assets/resize-embed.js`. `scripts/deploy.py --check` exited successfully. Launching `app.py` then exited with `FileNotFoundError`. The GitHub repository has no Actions workflow running the existing suite. Validate the actual deployment contents and exercise startup from that packaged tree. Run the offline regression suite on pull requests, with a separate opt-in hosted model check for releases. [Deployment check](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/scripts/deploy.py#L22) · [Startup dependency](https://github.com/HuayuanSong/storycut/blob/7b14d31e5938dc312adc69b23e16fb4efc4948dd/app.py#L295) · [Regression suite](https://github.com/HuayuanSong/storycut/tree/7b14d31e5938dc312adc69b23e16fb4efc4948dd/tests)

## Recommended release sequence

First protect in-flight edits and reset project-specific media, with browser regressions for both workflows. The dark-mode repair can ship independently. Then use the sundial expansion and reversed-scene response as regression cases for the writer. For each release, retain the current duration, caption, bundle and scrolling checks. The results support keeping the existing Qwen, Kokoro, LTX and FFmpeg pipeline while addressing these defects.
